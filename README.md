# API Documentation

## 1. Create Account

### Request

```http
POST /api/accounts
```

### Body

```json
{
  "name": "John Doe"
}
```

The client does not provide the initial balance.

The server creates the account with:

```text
balance = 0
```

---

## 2. Get All Accounts

```http
GET /api/accounts
```

Returns all accounts with their current balances.

---

## 3. Get Account Balance

```http
GET /api/accounts/:accountId/balance
```

Example:

```text
GET /api/accounts/ACCOUNT_ID/balance
```

---

## 4. Create Transaction

```http
POST /api/transactions
```

### Credit

```json
{
  "account_id": "ACCOUNT_ID",
  "type": "credit",
  "amount": 1000,
  "description": "Salary"
}
```

### Debit

```json
{
  "account_id": "ACCOUNT_ID",
  "type": "debit",
  "amount": 200,
  "description": "Purchase"
}
```

The `reference_id` is generated automatically by the backend.

The `created_at` timestamp is also generated by the server.

---

## 5. Get Transaction History

```http
GET /api/accounts/:accountId/transactions
```

### Pagination

```text
?page=1&limit=10
```

Example:

```text
GET /api/accounts/ACCOUNT_ID/transactions?page=1&limit=10
```

### Filter by type

Credit:

```text
?type=credit
```

Debit:

```text
?type=debit
```

Example:

```text
GET /api/accounts/ACCOUNT_ID/transactions?page=1&limit=10&type=credit
```

Transactions are returned in latest-first order.

---

## 6. Transfer Money

```http
POST /api/transactions/transfer
```

### Body

```json
{
  "source_account_id": "SOURCE_ACCOUNT_ID",
  "destination_account_id": "DESTINATION_ACCOUNT_ID",
  "amount": 300,
  "description": "Transfer"
}
```

### Transfer behavior

The API:

1. Checks that both accounts exist.
2. Checks that source and destination are different.
3. Checks the source account has sufficient balance.
4. Debits the source account.
5. Credits the destination account.
6. Creates a debit transaction.
7. Creates a credit transaction.
8. Commits the entire operation.

MongoDB transactions are used so the operation is atomic.

If any part fails, the complete transfer is rolled back.

---

# Validation Rules

### Account

- Name is required.
- Maximum account name length is 100 characters.
- Initial balance is always `0`.

### Transaction

- `account_id` must be a valid MongoDB ID.
- Type must be `credit` or `debit`.
- Amount must be greater than `0`.
- Description is optional.
- Description can contain up to 500 characters.

### Debit

A debit transaction is rejected when the account does not have sufficient balance.

### Transfer

- Source account must exist.
- Destination account must exist.
- Source and destination must be different.
- Amount must be greater than `0`.
- Source account must have sufficient balance.
